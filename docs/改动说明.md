# 改动说明（Label Horizon Paradox 项目改造方案与落地清单）

> 本文对应需求：把原开源 demo（DolphinDB + 全市场 + AlphaMLP + 回看1天 + h=1..10 + 目标h=10）
> 改造成 **Tushare + 沪深300 + LSTM + 回看10天 + h=1..5 + 目标h=5 + 5子账户 + TopN=30**，
> 并补上报告所需的图片/表格输出。所有改动均已落到工作区代码中，本文作为对照与运行指引。

---

## 1. 需求梳理与确认

| 维度 | 原 demo | 改动后 |
|---|---|---|
| 数据源 | DolphinDB（内部，不可用） | **Tushare**（2000积分档） |
| 股票池 | 全 A 股 / CSI300+500+1000 | **仅沪深300**（000300.SH，PIT 成分） |
| 回看窗口 | 1 天（单日截面 1×158） | **10 天**（序列 10×158） |
| 候选标签 h | 1..10（10个标准化累积标签） | **1..5**（5个标准化累积标签） |
| 推理目标 | h=10 | **h=5（固定）** |
| 停牌缺失 | 丢弃整行 | **前向填充 ffill** |
| 模型 | AlphaMLP（158→256→128→1） | **LSTM**（[B,10,158]→hidden→1） |
| 对比 | 暴力搜索 vs BLO | **有 BLO vs 无 BLO**（都换成 LSTM） |
| 子账户 | 10 个，持有 10 天 | **5 个，持有 5 天** |
| 回测 TopN | 100 | **30** |
| 输出 | 只有 CSV/日志 | **新增 PNG 图 + Markdown 汇总表**（含核心四曲线损失图） |

## 2. 对"改动初定方案.docx"的核对结论（发现的坑/补充）

1. **`limit_list_d`（涨跌停）需要 5000 积分**，你 2000 积分档**无法调用**（文档里写用
   `limit_list_d` 是个坑）。已改用"收盘价 vs 前收盘价"按板块涨跌停幅度近似：
   主板 10%、创业板（300/301）自 2020-08-24 起 20%、科创板 20%（沪深300基本不含）。
   若你后续升到 5000 积分，可把 `data_fetch/marketdata_db.py::get_limit_status` 换成
   `limit_list_d`，其余逻辑不变。见该函数注释。
2. **`suspend_d`（停牌）2000 积分即可用**，已接入；同时用"Tushare 日线停牌日无行"
   作为兜底（双重判定停牌）。
3. **`index_weight` / `adj_factor` 均 2000 积分起**，可用。
4. **日线无 VWAP**：Tushare `daily` 没有 VWAP，用 `amount*10/vol` 近似（amount 千元、
   vol 手），再乘复权因子得到后复权 VWAP，与原 demo 的 `vwap_adj = vwap_raw × adjfactor`
   口径一致（论文/demo 的标签即基于 VWAP）。
5. **R_AGG 手填是个坑**：原 `run_blo.py` 把 IC 排名硬编码，换数据后必须手改。已改为
   **自动重算**——`run_blo.py` 启动时读取 `run_search.py` 产出的 `alpha_agg.parquet`，
   计算 h=1..5 测试 IC 排名自动生成 R_AGG（找不到搜索 alpha 时用占位并告警）。
6. **样本量骤减的连锁影响**：只做沪深300，每日截面约 300 只，`len<20` 的丢弃条件不变
   （300 足够）。回测池子变小，故 TopN 取 30（约前 10%）。
7. **训练量/耗时**：h 数减半（5×15=75 次训练），但 LSTM + 二阶 BLO 更慢，BLO 的
   `N_SEED`/`WARMUP_SEEDS`/`N_ITERS` 可按需下调。
8. **回看窗口首尾损失**：凑不满 10 天窗口的股票当日丢弃（含上市前导 NaN，ffill 无法
   补前导缺失），因此测试期最开始的 9 个交易日不打分，属预期。

## 4. 运行顺序（你在本地跑，我不代跑）

```bash
# 0) 设置 Tushare Token（2000积分及以上）
set TUSHARE_TOKEN=你的token          # Windows

# 1) 数据：沪深300成分 + 日线（下载/生成 parquet）
python scripts/build_backtest_data.py

# 2) 因子：沪深300 Alpha158
python scripts/build_factors.py

# 3) 因子预处理缓存（69 tanh + 89 keep）
python scripts/cache_factors_processed.py

# 4) 无 BLO：暴力搜索 h=1..5（产出 IC 排名 + 无BLO 损失曲线数据）
python scripts/run_search.py

# 5) 有 BLO：双层优化（自动重算 R_AGG，产出 λ + BLO 损失曲线数据）
python scripts/run_blo.py

# 6) 回测：沪深300 TopN=30，5 子账户
python scripts/run_backtest.py --mode agg --topn 30

# 7) 出图/出表（核心四曲线损失图在这里生成）
python scripts/run_plot.py
```

## 5. 输出说明（报告素材）

`run_plot.py` 会生成（在 `results/figures/`）：

- `loss_curve_blo_vs_noblo.png` —— **必选项**：有 BLO / 无 BLO 在**训练集**与**验证集**
  的四条 MSE 损失曲线，画在同一张图里对比。
- `ic_ranking.png` —— h=1..5 的 IC/RankIC（呈现"标签 horizon 悖论"）。
- `lambda_distribution.png` —— BLO 学到的 λ 分布。
- `backtest_nav.png` —— 各 horizon 回测净值曲线 + 沪深300 基准。
- `summary.md` —— IC 排名、λ、回测指标的 Markdown 汇总表。

损失曲线的数据来源（供你二次加工）：

- 无 BLO：`results/losses/search_loss_agg.csv`（h=5 的每 epoch train/valid MSE，跨 seed 平均）。
- 有 BLO：`results/blo/blo_loss_agg.csv`（每 iter train/valid MSE，跨 seed/warmup 平均）。
- 说明：BLO 的 train 损失用固定子样本（每步评估省时），valid 损失用完整验证集；无 BLO 用完整训练集/验证集。
  两者 x 轴分别是 epoch 与 iter，属"训练进度"含义，画在同一张图便于趋势对比。
- 注意：**旧版 `blo_loss_agg.csv` 没有 `valid_loss` 列**，需重跑 `run_blo.py` 后再执行 `run_plot.py`。
